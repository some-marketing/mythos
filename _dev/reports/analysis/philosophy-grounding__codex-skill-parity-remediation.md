## Disconfirmation pass

The grounding lane searched for evidence that canonical command content is harness-neutral, current policy permits auto-application, the lifecycle transform generalizes, the adapter contains sufficient semantic information, and the dirty tree permits refresh. It found immediate counterevidence:

- `ground-in-philosophy` carries explicit Pi-only behavior.
- canonical harness policy says command surfaces and semantic behavior require review rather than automatic application;
- the lifecycle renderer contains narrow hand-authored capability distinctions;
- the Codex adapter lacks projection kinds and per-command overrides;
- extensive unrelated and untracked activity supports the custody stop condition.

This disconfirmation was as easy as confirmation, so semantic staging must precede bulk application.

## Tensions held

- strict parity versus harness truth;
- automation versus observed adoption;
- completeness versus custody;
- discoverability versus namespace restraint;
- one projection engine versus excessive centralized semantic authority.

## Required adjustments adopted by the plan

1. Stage candidates and apply only reviewed-safe classifications.
2. Add explicit projection kinds and per-command overrides; `UNKNOWN` blocks.
3. Use `ground-in-philosophy` as the first negative fixture.
4. Put the lifecycle mechanism through a short evidence-bearing probation.
5. Add provenance receipts and negative tests.
6. Keep one entry point but separate command, alias, direct-skill, and framework strategies.

The grounding lane identified T4, discovery precedes understanding, and T7, sender responsibility, as the governing through-lines.
