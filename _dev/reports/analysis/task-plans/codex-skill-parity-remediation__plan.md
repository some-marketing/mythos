## Matched framework

`meta/execution-normalization` scored 51%. Its cross-harness standardization pattern applies, but projection semantics, Codex packaging, framework-helper exposure, and multi-actor custody are gap work.

## Plan

### S0 — Prove and declare the projection contract

Run implementation in `~/.mythos-worktrees/mythos-codex-skill-parity-remediation` on `codex/skill-parity-remediation`. Adopt the lifecycle slice as probation evidence and implement a single projector with separate strategies for canonical commands, direct skills, aliases, and framework helpers. Capability comes from the real handler registry and explicit adapter overrides. Every candidate receives provenance, source hash, classification, capability tier, and review state. Unsafe or unknown candidates are staged and rejected. Negative fixtures cover Pi-specific semantics, adapter/handler disagreement, alias cycles, collisions, and command-to-project-skill aliases.

### S1 — Project reviewed-safe capabilities

From that same worktree, run candidate generation and apply only reviewed-safe changes into its `.agents/skills`. Prioritize daily operator vocabulary and governance. Resolve aliases dynamically. Use a collision-free, lineage-preserving namespace for framework helpers. Existing invalid or stale files may change only in exact-path custody batches; otherwise they remain named residuals.

### S2 — Verify and close

Run package validation, projection checks, alias and handler coverage, lifecycle tests, negative fixtures, privacy/path checks, instruction regeneration/validation, and fresh `codex exec` discovery or invocation receipts against that worktree. Obtain a distinct-family implementation review, repair blockers through an amendment, and debrief. Commit and pull-request work stays in `~/.mythos-worktrees/mythos-codex-skill-parity-remediation`; shared-checkout or worktree gate conflicts become explicit operator gates.

## Required gates

- No canonical-instruction writes.
- No bulk overwrite of `.agents`.
- Existing-file refresh requires a `CustodyRecord` with exact path, git status, current SHA-256, attribution, and operator-stamp reference; unknown attribution blocks.
- `UNKNOWN` blocks application.
- Alias names never become behavioral authority.
- Package validity, semantic review, runtime resolution, and enforcement remain separate claims.
- Consequence-grade and distinct-family review are required.
