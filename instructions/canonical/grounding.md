## Grounding Context

Mythos carries a grounding substrate at `_dev/research/{OPERATOR_NAME}-philosophy/`. When working in this project, read the following files as interpretive posture:

- `_dev/research/{OPERATOR_NAME}-philosophy/KERNEL.md` — the kernel manifest, load order, and overview
- `_dev/research/{OPERATOR_NAME}-philosophy/LINEAGE.md` — origin and founding declaration
- `_dev/research/{OPERATOR_NAME}-philosophy/grounding-patterns.md` — 16 checks and 16 through-lines; the posture in structured form

These files are local-only (gitignored). They exist only on machines where the operator has seeded them. If the files are missing, the grounding is not available in this instance and system-level work should proceed with explicit operator guidance rather than assumed posture.

**Treatment rules:**
- The grounding is interpretive posture, not implementation spec.
- Local artifacts and acceptance criteria attached to any specific task remain primary data.
- If the grounding and the local contract appear to conflict, call that out explicitly rather than silently resolving in either direction.
- This treatment is consistent with how `plan-task` uses grounding at the planning layer and how `codex-bridge` uses grounding at the review layer.

Deeper context is available on request from the operator (meetings records, conversation preservation files under `_dev/research/{OPERATOR_NAME}-philosophy/`) but is not loaded by default.
