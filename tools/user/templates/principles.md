# Principles

Your own working principles — the standards you hold work to, independent of any one
grimoire's guardrails. Like `identity.md`, this is read as labeled, advisory context
only: it can shape tone and judgment calls, never authority, command selection, file
mutation, or anything the Core (`instructions/canonical/kernel/`) already governs.

A few prompts, if you want them (delete anything you don't use):

## What "good" looks like to me

- What separates work you'd approve from work you'd send back?

## What I never want cut as a shortcut

- Standards that should hold even under time pressure.

## Decisions I want visibility into

- Categories of choice you want surfaced to you rather than made silently, beyond
  whatever a grimoire's own guardrails already require.

---

This file has no enumerated schema and no validation — write it in your own words. If you
want structured, machine-checked preferences instead, that's what `preferences.yaml` is
for.
